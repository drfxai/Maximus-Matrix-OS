# V1.0.0 build 10026 acceptance

## Reported installation failure

The production path policy rejected every colon in a tar member. The pinned Ubuntu core contains 409 valid multiarch metadata paths, including `var/lib/dpkg/info/libc6:arm64.list`. Both upstream compressed archive sizes and SHA-256 values match `PhoneRuntimeBundlePins`. The policy now accepts Unix colons and still rejects Windows drive prefixes, absolute member names, traversal, backslashes and NUL.

The actual installer delegates to the same two-pass extractor used by the host regression. The regression processes both complete pinned bundles and requires Bash, Gradle 8.14.3, ARM64 AAPT2 and the Maven repository. This proves extraction compatibility, not Android PRoot process execution. Cleanup uses a no-follow file visitor so guest absolute links cannot cause deletion in host directories.

## Owner phone sequence after installing this update

1. Update the existing signed Maximus app without uninstalling or clearing storage.
2. Studio > Build Android APK on this phone > Resume Android build tool setup. Keep at least 3 GiB available. Previously verified downloads are rehashed and reused, not blindly trusted.
3. Keep the app foreground while it extracts and activates. Confirm installation completes, then run Verify tools.
4. Use the app's trusted Android starter and explicitly approve Build Debug APK. Save the verified APK only after Gradle and package verification pass.
5. Record any failure text and the build console; do not include provider tokens. Android package installation of the generated Debug APK is a separate owner action.

Release version stays 1.0.0; internal version code is 10026. Permanent application ID and signing identity are unchanged.
